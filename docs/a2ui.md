# A2UI 1.0 shared agent presentations

Reference: [Google A2UI 1.0](https://a2ui.org/), released 11 November 2026. A2UI describes *what to display* with declarative data; the hosting client chooses trusted, native components. It is **not** a script generator or a replacement for authorization, tools, or verified business data.

## First implementation: intentionally narrow v1.0 subset

`PublicA2uiService` emits one v1.0 `createSurface` message with a unique `surfaceId`, Basic catalog ID, a flat list of component IDs, root `Column`, read-only `Card`/`Text` components, an attached `dataModel`, and `Button` actions restricted to the Basic catalog's `openUrl`. It uses *only* `PublicKnowledgeService::products()` and `::articles()`. Each response is bounded to four published results and creates no order, booking, file, query, or arbitrary mutation. Values are bound using `{"@path":"/items/0/title"}` style references; no HTML, CSS or JS is generated by the model.

- **Support**: successful responses from `POST /support/ask` optionally include an `a2ui` property for public product/article questions. The existing `reply`, tickets, user identity and private JSON conversation remain unchanged.
- **Enterprise**: successful `POST /admin/agent/ask` answers optionally include the same public presentation. This does not expose authenticated owner information to public tools; normal role guards, private Markdown and chat storage remain as before.
- **WebMCP**: `present_public_knowledge` is registered on public pages with the official polyfill, explicit bounded `inputSchema` and `outputSchema`. The tool calls `GET /api/knowledge/a2ui?view=products&limit=4` or `view=articles` using `credentials:omit`. Any standards-aware renderer can consume the returned A2UI data, but external browser agents must still support WebMCP discovery.
- **Existing native MCP STDIO**: ordinary product/article tools are unchanged. A2UI can later be transported through an authenticated remote MCP App; that is separate from merely registering browser WebMCP tools.

## Trust boundary and display policy

`assets/a2ui-public-renderer.js` implements a small **subset of the Basic catalog**, not the complete official A2UI renderer. It validates the catalog ID, version, component types, IDs, bindings, result count, safe navigation paths and allowed `openUrl` action before displaying content. Text is inserted as DOM text, not `innerHTML`. Buttons become native same-origin anchors only after a human click; no auto-navigation, checkout, script, arbitrary DOM creation, remote URL, owner-only tool or private session lookup is possible. Unsupported versions/components fail closed and the text answer remains visible.

The same responsive styles come from `assets/css/a2ui-public.css`, using the site's maroon/gold design tokens rather than model-authored styling.

## What is NOT implemented yet

This first slice does not provide the full A2UI 1.0 renderer, streaming `updateComponents`/`updateDataModel`, general `callAgentFunction` or `callRendererFunction`, two-way validation forms, native iOS/Android SDKs, seller actions or model-generated arbitrary layouts. Product/guide cards are selected deterministically by the server from published data. Future updates may extend the approved catalog incrementally, with formal capability negotiation and explicit, authenticated user approval for mutations.

## Verification

`tests/public-a2ui.php` tests the generated message envelope, bounded public source, unpublished/future filtering, safe paths/components and unique surfaces. `tests/a2ui-public-browser.cjs` tests the official `@w3c/webmcp-polyfill@0.1.1` in Chromium alongside the safe renderer, including tool discovery, tool invocation, input/output declaration, XSS text rendering, cross-origin and `javascript:` URLs and unknown components. Both are part of CI.

A WebMCP-enabled browser that can execute the tool is **not equivalent to direct access inside an ordinary ChatGPT conversation**. For that, expose an independently authorized remote Streamable HTTP MCP application/connector with proper consent, scoped capabilities and safe results. Do not expose private MD, JSON sessions or admin tools via unauthenticated WebMCP.

The separate post-merge `webmcp_acceptance` GitHub Actions job (after the live SHA match) opens the actual public shop in Chromium, calls `document.modelContext.getTools()` and `executeTool()` on all four public tools, and renders the returned A2UI card. It is browser-level production evidence, **not** proof that this ordinary ChatGPT conversation has the site's WebMCP registered as one of its own tools. If the external browser service is unavailable, this independent CI test is the supported read-only production verification.
